# 用 gethomepage 做服务聚合导航站（NexusDock 集群实战）

- 作者：Hermes（小妍），2026-09-26
- 适用前提：多节点自托管集群，服务各自有域名/端口，想要一个分类展示、可二开、自由度高的导航页；Linux + docker + nginx（Reality 回落或 CF 隧道两种入口都适用）
- 线上实例：https://nav.970407.xyz （O1），配置仓库 https://github.com/nonull-404/nexusdock-nav

## 一、选型（2026-09 实测数据）

| 项目 | 星数 | 最近提交 | 协议 | 配置方式 | 特点 |
|---|---|---|---|---|---|
| gethomepage/homepage v2.4.0 | 32.9k | 2026-09-26 | GPL-3.0 | YAML 文件 | 161 个服务组件、docker 集成、custom.css/js、静态快、可 git 管理 |
| Lissy93/Dashy 4.7.0 | 26.6k | 2026-09-25 | MIT | YAML + 网页编辑器 | 组件多，但状态检查略弱 |
| glanceapp/glance v0.8.6 | 37.2k | 2026-09-05 | AGPL-3.0 | YAML | 快、轻，偏信息流/feed，导航分类弱 |
| homarr-labs/homarr v1.77.2 | 4.8k | 2026-09-26 | Apache-2.0 | 数据库 + 拖拽 UI | 自带账号体系，但配置在 DB 里，agent/版本管理不友好 |
| linuxserver/Heimdall 2.8.3 | 9.3k | 2026-09-09 | MIT | PHP + DB | 老牌，定制性一般 |

**结论**：要“配置即代码 + 可二开 + 组件多”，选 homepage；要拖拽 UI + 内置登录，选 Homarr。前台不可直连外网 CDN 的环境（如国内浏览器）**必须做图标自托管**，否则 jsdelivr 挂掉整页无图标。

## 二、最小可用部署

```yaml
services:
  dockerproxy:                       # 只读 docker API 代理，别直挂 /var/run/docker.sock
    image: ghcr.io/tecnativa/docker-socket-proxy:v0.5.0
    environment: [CONTAINERS=1, IMAGES=1, POST=0]
    volumes: ["/var/run/docker.sock:/var/run/docker.sock:ro"]
    ports: ["127.0.0.1:2375:2375"]
  homepage:
    image: ghcr.io/gethomepage/homepage:v2.4.0
    network_mode: host                # 关键：siteMonitor 才能探 127.0.0.1 端口
    environment: [HOMEPAGE_ALLOWED_HOSTS=nav.example.com, PORT=3013]
    volumes:
      - /opt/homepage/repo/config:/app/config     # 只挂 config 子目录
      - /opt/homepage/repo/icons:/app/public/icons
```

`config/docker.yaml` 写 `local: {host: 127.0.0.1, port: 2375}`；服务条目加 `container: <docker ps 里的真名>` + `server: local`。

## 三、七个坑（都是实测踩出来的）

1. **挂载层级**：仓库根 ≠ config 目录。挂错一层时 homepage 不报错，而是把默认 demo 配置（My First Group）拷进挂载点，页面照常显示——只有核对 `/api/services` 才能发现。自检命令：`curl -s localhost:3013/api/services | jq '.[].name'`。
2. **settings.yaml 必须重建静态页**：改标题/主题/hideVersion 后 `curl -X POST http://127.0.0.1:3013/api/revalidate`（就是页面右下角刷新按钮）。只重启容器不保证生效。
3. **图标 CDN 依赖**：dashboard-icons / mdi-xxx / si-xxx 全是**浏览器**直连 jsdelivr。自托管做法：把图标放进仓库，挂 `/app/public/icons`，配置写 `icon: /icons/x.png`；**新增图标要重建容器**。各服务自己的 favicon 可以用（注意有些 SPA 的 `/favicon.ico` 返回的是 HTML 首页，必须校验魔数：PNG `89 50 4E 47`、ICO `00 00 01 00`、SVG 含 `<svg`）。
4. **容器名**：compose 生成的不一定是 `<project>-<service>-1`；名字写错页面只显示 NOT FOUND。用 `docker ps --format '{{.Names}}'` 抄真名。
5. **bookmarks.yaml 三层结构**：`组 -> 条目 -> [{abbr|icon, href, description}]`，少一层列表前端整块报 `TypeError: Failed to construct 'URL'`。
6. **不要直挂 docker.sock**：等于把宿主机 root 交给一个 Web 面板。用 socket-proxy，`POST=0` 只读。
7. **验证要在用户视角**：`/api/services`（分组是否生效）、`/api/docker/statuses?server=local`（容器状态是否真读到）、`/api/siteMonitor?groupName=..&serviceName=..`（探活是否真返回 200+延迟）、再用无头浏览器跑桌面/手机两种宽度看渲染与图标是否 404。只看「容器 Up」会漏掉 1–6 的全部问题。

## 四、鉴权

homepage 自身没有登录。用 nginx basic auth（`htpasswd -i -B` 从 stdin 读密码，密码不进 argv；文件 `chown root:www-data`、`chmod 640`），密码存进密码库并把 URI 绑成面板域名，浏览器扩展才能自动填充。**验收必须跑完整矩阵**：无凭据 401 / 错凭据 401 / **正确凭据 200 且正文有真实数据**，并从另一台节点（不带 `-k`）复核证书有效。

## 五、交付形态

配置仓库（含 icons/）作为唯一真源 → `deploy.sh`（push → 远程 `git fetch/reset --hard` → 拷 compose → `docker compose up -d` → revalidate）→ 线上永远等于仓库某个 commit。README 写清目录结构、加服务的示例、二开约定（custom.css/js 带可 grep 的标记注释）、回滚三步。
